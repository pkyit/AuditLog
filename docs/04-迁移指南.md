# 迁移指南：从技术原型迁移到企业级版本

**适用对象**：已使用 `legacy/audit-log-prototype` 中 `com.github.pkyit.module.audit` 的项目。

**结论先行**：**可以平滑迁移，但必须评估 3 处行为变更**（第 3 节）。
其中「身份来源」与「事务回滚」两项是**有意的破坏性变更** —— 它们修的正是原版本的致命缺陷。

---

## 1. 依赖替换

原版本没有可发布的构件（单模块、`1.0-SNAPSHOT`、无 `distributionManagement`、无 LICENSE），
因此原本应是**源码拷贝**接入。现在改为标准依赖：

```xml
<!-- 删除：源码拷贝的 com.github.pkyit.module.audit 包 -->

<!-- 新增 -->
<dependency>
    <groupId>io.github.pkyit</groupId>
    <artifactId>audit-log-spring-boot-starter</artifactId>
    <version>1.0.0</version>
</dependency>
```

> 注意包名由 `com.github.pkyit.module.audit` 变为 `io.github.pkyit.auditlog.*`。
> 需要一个次要版本的兼容层请提 issue。

---

## 2. 注解与配置对应关系

### 2.1 `@EnableAuditLog`（可选保留）

```java
// 原用法：扫描包，用自制扫描器收集注解
@EnableAuditLog(scanBasePackages = {"com.example.controller"})

// 新版本：通常**直接删除**该注解，自动配置即生效
// 元数据来源改为 Spring 真实的 HandlerMapping，不再做类路径扫描

// 若确实需要限制范围，属性名有变化：
@EnableAuditLog(basePackages = {"com.example.controller"})   // scanBasePackages 仍兼容
```

**为什么不再需要扫描包**：原实现用 `ClassUtils.forName` 提前加载包内所有类，
会触发静态初始化并可能因可选依赖缺失导致**应用启动失败**；且用
`getDeclaredMethods + isAnnotationPresent`，**不识别接口/父类上的注解**。
新实现只遍历 Spring 已注册的 Handler，天然规避这两类问题。

### 2.2 `@AuditLog`

| 原属性 | 新属性 | 说明 |
|---|---|---|
| `value` / `name` | 同名 | 完全兼容 |
| `logHeaders` | 同名 | 完全兼容（默认 `true`） |
| `logRequestParams` | 同名 | 完全兼容（默认 `true`） |
| `logResponseParams` | 同名 | **默认值由 `true` 改为 `false`**（见 3.3） |
| `sensitiveParams` | 同名 | 完全兼容：仍作为**额外**敏感字段名 |
| — | `actionType` | 新增：动作类型枚举（`QUERY`/`MUTATE`/`EXPORT`…） |
| — | `resourceType` / `resourceId` / `resourceIdParam` | 新增：资源标识 |
| — | `sensitive` | 新增：标记敏感操作 |
| — | `tags` | 新增：自定义标签 |
| — | `ignore` | 新增：类级标注后单独排除某方法 |

**建议**：为每个审计方法补上 `actionType` 与 `resourceIdParam`。
没有它们，审计记录无法按动作类型聚合、无法定位到具体资源，
查询时只能靠 `operation` 文本模糊匹配。

### 2.3 配置项

原版本**没有任何配置模型**（无 `@ConfigurationProperties`、无 `@Value`），
全部行为固化在注解与代码里。新版本引入 `audit.log.*` 配置（完整清单见 README 第 4 节）。

**原 README 中记载的这些配置项从未存在过，不要照搬**：
`basePackages`、`logRequest`、`logResponse`、`sensitiveHeaders`、
`${audit.log.enable:true}` 属性占位符。新版本对应的真实配置是：
`audit.log.collector.method.*`、`audit.log.masking.sensitive-headers`、`audit.log.enabled`。

## 3. 必须评估的行为变更（重要）

### 3.1 【破坏性】身份来源改为认证上下文

**原行为**：`String userId = request.getHeader("userId")` —— 任意客户端可伪造身份。
**新行为**：主体来自 `PrincipalResolver` 链，默认只有认证上下文（Spring Security）与匿名兜底。

**对你的影响**：
- 如果之前靠手工传 `userId` 请求头，新版本会记为 `ANONYMOUS`（这是正确的）。
- 需要保留原行为时，显式开启（并承担风险）：

```yaml
audit:
  log:
    identity:
      header-principal-enabled: true
      principal-id-header: userId        # 与原行为对齐
```

开启后主体类型为 `TRUSTED_HEADER`，审计消费方可据此判断可信度。
**生产环境必须确保应用不可被外部直连**（只能经可信网关访问）。

**推荐做法**：提供自定义 `PrincipalResolver` 读取你们自己的认证上下文并返回
`PrincipalType.AUTHENTICATED`，这样才具备不可否认性。

### 3.2 【破坏性】事务回滚不再记为成功

**原行为**：事件在 `finally` 中发射，回滚也记 `responseCode=200`。
**新行为**：`afterCompletion` 捕获真实事务结果；默认**回滚不产生记录**。

**对你的影响**：
- 原本依赖"回滚也会留一条记录"的对账逻辑需要调整；
- 需要保留该记录时：

```yaml
audit:
  log:
    drop-on-rollback: false     # 记录会带 outcome=ROLLBACK + rolledBack=true
```

**注意**：无论哪种模式，都不再会出现"回滚被记成成功"。

### 3.3 响应参数默认不采集

**原行为**：`logResponseParams` 默认 `true`，但实际记录的是 `returnValue.toString()`
（通常是 `ArrayList@1a2b` 这类无意义内容，且可能触发懒加载异常）。
**新行为**：默认 `false`；开启后记录的是**响应元信息**（状态码、内容类型），
不记录正文 —— 采集正文需包装输出流，会改变流式/大响应行为。

**对你的影响**：如果下游依赖响应正文，需要自行实现响应包装扩展。

### 3.4 记录结构变化

`AuditLogDO`（13 个平铺字段）→ `AuditRecord`（不可变，含主体类型、租户、traceId、
动作类型、资源、结果枚举、错误归因、哈希链字段）。

字段对应：

| 原字段 | 新字段 |
|---|---|
| `id`（硬编码 `121212L`） | `getId()`（全局唯一） |
| `userId` | `getPrincipalId()` + `getPrincipalType()` |
| `operationName` | `getOperation()` + `getActionType()` + `getResourceType/Id()` |
| `clientIp` | `getClientIp()`（默认不信任代理头） |
| `requestUri` / `requestType` | `getRequestUri()` / `getHttpMethod()` |
| `requestParams` / `responseParams` | `getRequestPayload()` / `getResponsePayload()`（`Payload` 结构） |
| `requestHeaders` | 记录在 `getTags().get("headers")` |
| `responseCode` | `getHttpStatus()` + `getOutcome()` |
| `duration` | `getDurationMillis()` |
| `exceptionInfo` | `getError()`（类型 + 消息 + 根因） |
| `createTime` | `getEventTime()` / `getReceivedTime()` |

**兼容性**：`legacy` 中的 `AuditLogDO` 未在新版本保留别名。
如你的下游代码直接消费该结构，需要按上表调整（这是一次性工作，且新结构信息量更大）。

### 3.5 存储需要显式配置

**原行为**：硬编码 `log.info` 输出（且 `AuditLogListener` 是 `@Component`，
在外部 jar 场景下若不在组件扫描路径内则**根本不会注册**，导致事件无人消费、审计静默全丢）。
**新行为**：`AuditStore` SPI + 三种内置实现，默认 `logging`（启动会告警）。

```yaml
audit.log.store.type: json-file     # 或 jdbc
```

## 4. 迁移检查清单

- [ ] 替换依赖坐标，删除源码拷贝的 `com.github.pkyit.module.audit` 包
- [ ] 决定是否保留 `@EnableAuditLog`（通常可删除）
- [ ] 为审计方法补 `actionType` / `resourceType` / `resourceIdParam`
- [ ] **决定身份来源**：开启 `header-principal-enabled` 或提供自定义 `PrincipalResolver`
- [ ] **决定回滚语义**：保持默认 `drop-on-rollback=true`，或改为 `false` 并调整下游
- [ ] 配置生产存储（`json-file` 或 `jdbc`），确认启动日志中"非合规存储"告警消失
- [ ] 配置 `chain.enabled=true` + `chain.secret`（从密钥管理注入，不要写进配置文件）
- [ ] 接入指标告警：`audit.pipeline.dropped`、`audit.pipeline.journal.rejected`、`audit.store.deadletter`
- [ ] 核对 `/actuator/auditLog` 的收录清单，确认预期的方法都在里面
- [ ] 压测：**必须测"采集全开"的配置**（原版本的 18000 QPS 取自关闭全部采集开关的端点，不具参考性）
- [ ] 检查原 README 中记载的配置项（`basePackages` 等）是否被误用 —— 它们从未存在过

## 5. 迁移后你会额外得到什么

| 能力 | 原版本 | 新版本 |
|---|---|---|
| 认证失败 / 401 / 403 / 404 审计 | ❌ 完全漏采 | ✅ 边界通道覆盖 |
| 身份不可伪造 | ❌ 请求头可伪造 | ✅ 认证上下文 + 来源标注 |
| 事务回滚语义正确 | ❌ 回滚记成成功 | ✅ 可配置且不会记成成功 |
| 敏感信息脱敏 | ⚠️ 大小写敏感、不管报文体 | ✅ 大小写不敏感 + 递归字段 + 内容正则 |
| 不丢数据 | ❌ 无持久化、可静默丢弃 | ✅ 有界队列 + WAL + 重试 + 死信 + 指标 |
| 停机不丢队列 | ❌ 直接丢 | ✅ `SmartLifecycle` 排空 |
| 防篡改 | ❌ 无 | ✅ 哈希链 / HMAC 链 + 可校验 |
| 保留期与轮转 | ❌ 无（只增不减） | ✅ 文件轮转 + 历史清理 |
| 可观测性 | ❌ 无指标 | ✅ 指标 + 健康检查 + 诊断端点 |
| 配置模型 | ❌ 无 | ✅ `audit.log.*` 全量配置 |
| 扩展点 | ❌ 需改源码 | ✅ 11 个 SPI |
| 静默失效防护 | ❌ 静默跳过 | ✅ 启动校验 + 未命中指标 + 收录清单端点 |
| 许可证 | ❌ 未声明 | ✅ Apache-2.0 |
