# Java 注释规范（本仓库强制）

本文件是代码注释的**唯一标准**。所有注释改写以本文件为准。

## 一、总原则

注释解释**代码本身表达不出来的信息**，只写三类内容：

1. **契约**：前置条件、后置条件、副作用、异常语义、返回值边界。
2. **非显而易见的 WHY**：为什么必须这样做。必须用**非人称**陈述（"必须…否则…"），
   而不是开发过程叙事（"我一开始…后来发现…"）。
3. **并发与生命周期**：线程安全性、可见性、所有权、释放责任。

读注释的人关心的是**这段代码怎么用、有什么坑**，不关心它**是怎么被写出来的**。

## 二、禁止出现的内容（AI 味来源）

| 类别 | 禁止示例 |
|---|---|
| 第一人称 | `我一开始按设想读…`、`我们改成…` |
| 开发历程 | `原先`、`最初`、`曾经`、`此前`、`历史上`、`一开始`、`原实现是…` |
| 实测叙事 | `实测：404 被记成 null`、`实测踩到`、`踩坑记录`、`教训：` |
| 评审过程 | `修复评审缺陷 H1`、`自评审 D1`、`评审发现` |
| 强调符号 | `✅`、`❌`、`⚠️`、`！！`、`**注意**` |
| 自我评价 | `值得记录`、`如实记录`、`刻意取舍`、`这正是…的例子` |
| 反问/感叹 | `为什么？因为…`、`这就糟了` |
| 版本考古 | `Spring 6.2 没有该方法`（除非是当前必须绕开的约束，且需写成约束而非发现史） |

## 三、应当保留并写好的内容

- 不变量："返回的列表不可变。" 
- 并发："本方法可被多线程并发调用；内部使用 CAS。"
- 所有权："调用方负责释放返回的缓冲区。"
- 约束："响应提交后状态码不可再改，因此必须在提交前读取。"
- 退化行为："解析失败时回退为 UNKNOWN，不抛异常。"
- 规范引用：`@see`、`{@link}`、ADR 编号。

## 四、格式要求

- 类型与 public/protected 成员：必须有 Javadoc（`/** … */`）。
- Javadoc 首句为摘要句，以句号结尾，独立成段。
- 使用 `@param` / `@return` / `@throws`，不写空话（"参数 x" 这种等于没写）。
- 行内注释用 `//`，放在被解释代码**上一行**；行尾注释仅用于极短标注。
- 段落之间用空 `*` 行分隔。
- 语言：中文；技术名词保留英文原文（如 `backpressure`、`DataBuffer`）。

## 五、改写示例

**反例（开发叙事）**

```java
// 这里曾经也尝试过读 exchange 的 BEST_MATCHING_HANDLER 属性补语义，
// 但实测该属性在这个位置读不到（DispatcherHandler 把属性写在 mutate 出来的
// 另一个 exchange 上，而 Spring 6.2 的 Builder 没有 attributes(...)）。
// 语义完全交给 ReactiveSemanticChannelProcessor：那里能拿到 HandlerMethod。
// 只保留一处很重要：两处都做会变成"先到者胜"。
captureService.finish(...);
```

**正例（约束陈述）**

```java
// 语义填充的唯一入口是 ReactiveSemanticChannelProcessor。语义元数据只能填充一次，
// 多处填充会因执行顺序不确定而丢失按请求解析的字段。
captureService.finish(...);
```

**反例（第一人称心得）**

```java
/**
 * 为什么要专门写用例：我踩过一次坑，于是决定固化这条事实。
 */
```

**正例（契约）**

```java
/**
 * 校验快照与外层交换器共享同一属性表。
 *
 * <p>属性表的共享性是语义通道成立的前提：若 {@code mutate()} 复制属性表，
 * 内层写入的 Handler 匹配结果将无法被过滤器读取。
 */
```

## 六、硬约束（改写时必须遵守）

1. **只改注释**。不得改动任何代码 token、字符串字面量、注解、import、缩进结构。
2. 不得删除 `@Override`、`@Deprecated` 等注解；不得调整成员顺序。
3. 不得改动 Javadoc 中的 `{@link}` / `{@code}` 目标，除非目标已不存在。
4. 注释行数可增可减，以**信息密度**为准，不以长度为目标。
5. 文件编码保持 UTF-8 无 BOM，换行符保持原样（CRLF 或 LF 不变）。
