# audit-log 整改方案（企业级可插拔日志审计框架）

> 本文档是整改的架构契约。评审结论见 `docs/01-架构评审报告.md`，决策记录见 `docs/03-架构决策记录(ADR).md`。

---

## 0. 整改目标与非目标

### 目标
把「技术演示」重建为**企业级、可插拔的日志审计组件**：任意 Spring Boot 项目加一个依赖 + 一行配置即可启用，默认安全、失败可观测、数据不丢、历史可验。

### 非目标
- 不做审计数据的可视化查询 UI（只提供存储 SPI 与 JDBC 参考实现）；
- 不做分布式事务级别的「审计与业务强一致」（提供可选的一致性模式，默认最终一致）；
- 不追求「零开销」——审计必须付出成本，目标是把成本做成**可配置、可度量、可背压**。

## 1. 四条审计不变量（一切设计的约束条件）

| # | 不变量 | 设计手段 |
|---|---|---|
| I1 | **身份不可伪造** | 主体只能来自认证上下文 `PrincipalResolver` 链；显式开关才允许读信任请求头；记录主体来源 `principalSource` |
| I2 | **结果真实** | 采集与提交边界对齐（`AFTER_COMMIT` 补齐模式 / 同事务模式）；状态码取自真实响应；记录异常类型 + 根因 |
| I3 | **事件不丢** | 有界队列 + 显式背压策略；降级写本地 WAL（sidecar journal）并可在恢复后重放；优雅停机排空；丢弃/降级一律计入指标并告警 |
| I4 | **历史不可篡改** | 单调 `seq` + `prevHash` + `recordHash` 哈希链，可选 HMAC 签名；审计存储与业务日志物理分离；保留期与归档策略 |

## 2. 目标架构

### 2.1 模块划分（Maven 多模块）

```
audit-log/                        父 POM：版本统一、插件与编码治理
├── audit-log-core/               纯框架内核，不依赖 Servlet
│   ├── api/            对外 SPI 与不可变模型（唯一稳定契约面）
│   ├── model/          AuditRecord / AuditContext / Outcome / ActionType / Payload
│   ├── mask/           脱敏引擎（字段路径 + 正则 + 掩码）
│   ├── serialize/      快照序列化（请求线程内完成）
│   ├── chain/          哈希链（发起号、链状态、校验）
│   ├── store/          AuditStore SPI + 默认实现（Logging/JsonFile）
│   ├── pipeline/       有界队列 + 背压 + WAL 降级 + 批量投递 + 重试 + 死信
│   ├── wal/            本地落盘日志（WAL）与恢复重放
│   └── metrics/        指标抽象（无 micrometer 硬依赖）
├── audit-log-spring-boot-starter/
│   ├── AuditLogProperties        全量配置模型（@ConfigurationProperties）
│   ├── AuditLogAutoConfiguration 条件装配 + 自动配置注册
│   ├── method/                   方法级采集（HandlerAdapter 扩展，可选关闭）
│   ├── servlet/                  Filter 边界兜底采集（认证失败/403/404/绑定失败）
│   ├── context/                  异步上下文传播（MDC / SecurityContext / 请求上下文）
│   ├── validation/               启动期校验 + 与 HandlerMapping 交叉校验
│   └── actuator/                 健康检查 + 指标 + 管理端点（可选）
└── audit-log-samples/            示例应用（保留原有端点，演示全部能力）
```

**为什么是三个模块**：`core` 提供契约与流水线（可被非 Web 场景直接复用），`starter` 提供采集与自动装配（可插拔的落点），`samples` 与框架隔离（解决原「示例混装进框架」的问题）。

### 2.2 分层与依赖方向

```
业务代码 ──注解──▶ starter(采集) ──▶ core(流水线/契约) ──SPI──▶ 用户实现(存储/脱敏/主体)
                                        │
                                        └──▶ 默认实现(JsonFile/WAL/Logging)
```

依赖单向、`api` 包只依赖 JDK + Jackson（不依赖 Spring），保证 SPI 可被任意实现复用。

### 2.3 采集模型（解决 F5 / M1）

采用**双通道采集**，取代原来「只挂 doInvoke」的单点：

| 通道 | 落点 | 覆盖 | 默认 |
|---|---|---|---|
| **边界通道** | `OncePerRequestFilter` | 全部请求：认证失败、401/403、限流、404、绑定失败、静态资源、响应码 | 开 |
| **语义通道** | `HandlerMethod` 扩展（`WebMvcRegistrations`，可关闭） | 操作名、动作类型、资源 ID、变更前后快照、耗时 | 开 |

- 边界通道保证**不漏**（解决 F5）；
- 语义通道提供**审计语义**（解决 H5）；
- 两者用 `requestId` 关联，语义通道存在时**补齐并覆盖**边界通道的粗粒度记录（同一 `requestId` 只落一条，避免重复）；
- 语义通道可整体关闭（`collector.method.enabled=false`）→ 纯 Filter 模式，不与宿主 `WebMvcRegistrations` 冲突（解决 M1 的互斥风险）。

### 2.4 一致性与结果真实性（解决 F2 / F3）

`AuditRecord.outcome` 与状态码的真实来源：

- 状态码：边界通道在 `afterCompletion` 读 `HttpServletResponse.getStatus()`；语义通道若早于响应提交，则从边界通道的最终记录中取真实值；
- 异常：记录**异常类型 + message + 根因链摘要（可配置是否含堆栈）**；
- 事务：语义通道捕获到的记录先入**待定缓冲**，由事务结果决定：
  - `commitMode=EVENTUAL`（默认）：记录立即投递，`outcome` 由真实响应决定；
  - `commitMode=AFTER_COMMIT`：记录挂到 `TransactionSynchronization`，提交后投递、回滚则改写为 `ROLLBACK` 并投递（**不再出现「回滚记成成功」**）；
  - `commitMode=REQUIRED_SAME_TX`：记录写入由用户 `AuditStore` 在同一事务内落库（强一致，需用户存储支持）。

### 2.5 发布与背压（解决 H2 / H3）

```
采集(请求线程, 只做快照) ──offer──▶ 有界环形队列
                                      │ 满
                                      ├─ BLOCK(默认不选)：阻塞，压回 SLA
                                      ├─ SPILL(默认)：写本地 WAL，计入 spilled 指标，后台重放
                                      ├─ DROP_OLDEST：丢最旧并计数（明确告知合规风险）
                                      └─ FAIL_FAST：抛异常中断业务（仅强一致合规场景）
队列 ──▶ 单/多批量消费者 ──▶ AuditStore.batchSave
                              ├─ 失败 → 指数退避重试 N 次
                              └─ 仍失败 → 死信（WAL deadletter）+ 指标 + 告警钩子
停机：SmartLifecycle 排空队列 + flush WAL（解决「停机丢队列」）
```

**关键决策**：默认背压策略为 `SPILL`（不丢、不阻塞业务，代价是磁盘），因为审计的核心诉求是「不丢」，而 `CallerRunsPolicy` 式的「压回业务线程」会破坏 SLA。

### 2.6 脱敏（解决 H4）

- **大小写不敏感**的字段名匹配；
- **递归 JSON 路径匹配**：`$.user.password`、`$.data[*].idCard`、`*.token`；
- **正则识别**：手机号、身份证、银行卡、邮箱、JWT/Bearer；
- **掩码策略**：`FULL`（全掩）/ `PARTIAL`（保留首尾）/ `HASH`（不可逆摘要）；
- **保守默认**：默认开关 `mask.unknownHeaders=false`，但 `Authorization/Cookie/Set-Cookie/X-Auth-Token/Proxy-Authorization` 恒在默认黑名单，且**不受用户配置覆盖**（安全默认不可被误关）；
- 脱敏在**请求线程内**完成（进队列的是已脱敏快照，避免异步线程访问已失效对象）。

### 2.7 防篡改（解决 H3 / I4）

- `AuditRecord` 增加 `seq`(单调)、`prevHash`、`recordHash`、`signature`(可选 HMAC-SHA256)；
- 由 `AuditHashChain` 在投递前按批次串行计算，存储侧必须 **append-only**；
- 提供 `AuditChainVerifier` 用于离线/在线校验；提供 JDBC 表结构（含唯一索引与只增权限建议）；
- 记录 `schemaVersion` 以支持未来格式演进。

### 2.8 可插拔与自动装配（解决 M2 / M3 / M5）

- `@EnableAuditLog` 改为 `@Import(AuditLogAutoConfiguration.class)` + 基础包自动探测，**不再扫描类路径构造 `Map<Method, BO>`**；
- 全部默认实现使用 `@ConditionalOnMissingBean` → 用户提供同类型 Bean 即接管；
- 全部能力可开关：`enabled`、`collector.boundary.enabled`、`collector.method.enabled`、`store` 选择、`chain.enabled`、`actuator.enabled`；
- 通过 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 注册 → 依赖引入即生效，**无需注解**（注解仅用于「要改包扫描范围」等场景）；
- 交付物补齐 `LICENSE`、`developers`、`scm`、`url`、非 SNAPSHOT 版本策略、`CHANGELOG`、兼容矩阵。

### 2.9 可观测性与启动校验（解决 H1）

- **启动期**：方法与 `RequestMappingHandlerMapping` 交叉校验 —— 「在 HandlerMapping 中且带 `@AuditLog` 但未被配置收录」时按 `validation.failOnMismatch` 决定 `报错/告警`（默认告警，避免把宿主应用搞崩）；
- **运行期指标**：`collected` / `skipped` / `masked` / `enqueued` / `rejected` / `spilled` / `dropped` / `delivered` / `failed` / `retried` / `deadletter` / `queueDepth` / `collectLatency`；
- **健康检查**：`auditLog` 健康指示器，队列水位 / WAL 积压 / 存储可用性；
- **失败钩子**：`AuditFailureHandler` SPI（默认 WARN 日志），供接入告警。

### 2.10 安全默认

| 项 | 默认值 | 理由 |
|---|---|---|
| 记录请求体 | `true`（但强制脱敏 + 长度上限 4KB） | 审计需要 |
| 记录响应体 | `false` | 响应易含大对象/敏感数据，默认关闭 |
| 记录请求头 | `true`（黑名单恒生效） | 审计需要 |
| 记录堆栈 | `false`（仅类型+根因摘要） | 避免信息泄漏与体积 |
| 可信任代理头 | `false` | 防伪造 IP |
| 主体来源 | `SECURITY_CONTEXT` | I1 |
| 背压 | `SPILL` | I3 |
| 存储 | `logging`（明确不持久） | 默认不写坏用户环境，启动校验会告警 |
| 链 | `enabled=false` | 有性能成本，需显式开启 |

## 3. SPI 契约清单（唯一稳定面）

| SPI | 职责 | 默认实现 |
|---|---|---|
| `PrincipalResolver` | 主体解析（链式，有序） | `SecurityContextPrincipalResolver` → `HeaderPrincipalResolver`(默认关) → `AnonymousPrincipalResolver` |
| `ClientIpResolver` | 真实 IP（信任代理链配置） | `DefaultClientIpResolver` |
| `TenantResolver` | 租户解析 | `NoopTenantResolver` |
| `AuditSerializer` | 快照序列化 | `JacksonAuditSerializer` |
| `AuditMasker` | 脱敏 | `RuleBasedAuditMasker` |
| `AuditStore` | 存储（`save` / `batchSave`） | `LoggingAuditStore`、`JsonFileAuditStore`、`JdbcAuditStore`(starter) |
| `AuditFailureHandler` | 失败钩子 | `LoggingAuditFailureHandler` |
| `AuditMetrics` | 指标 | `SimpleAuditMetrics`（starter 有 micrometer 时用 `MicrometerAuditMetrics`） |
| `AuditJournal` | WAL 降级与重放 | `FileAuditJournal` |
| `AuditChain` | 哈希链 | `HmacAuditChain` / `NoopAuditChain` |
| `AuditActionResolver` | 注解 → 动作语义 | `AnnotationActionResolver` |

## 4. 兼容与迁移

- 保留 `@EnableAuditLog` 与 `@AuditLog` 的全限定名与既有属性语义（`scanBasePackages`、`enable`、`value`/`name`、`logHeaders`、`logRequestParams`、`logResponseParams`、`sensitiveParams`）→ **存量代码零改动**；
- 新增属性向后兼容地扩展（`actionType`、`resource`、`resourceIdSpEL`、`maskRules`、`commitMode` 覆盖等）；
- 原 `AuditLogDO` 保留为 `@Deprecated` 兼容别名（映射到新 `AuditRecord`），一个次要版本后移除；
- 版本策略：`1.0.0` 起语义化版本，`CHANGELOG` 记录破坏性变更。

## 5. 验收标准

| # | 验收项 | 判定方式 |
|---|---|---|
| A1 | 任意 Spring Boot 项目仅加依赖即可启用 | samples 不写 `@EnableAuditLog` 也能采集（自动配置生效） |
| A2 | 伪造 `userId` 请求头无法影响审计主体 | 集成验证：带 `userId` 头请求，主体仍为认证主体 |
| A3 | 业务回滚不再被记为成功 | 集成验证：`@Transactional` 回滚端点 → 记录为 `ROLLBACK`（AFTER_COMMIT 模式）或按模式定义一致 |
| A4 | 认证失败/403/404 被记录 | 集成验证：无权限、错误路径均产生审计记录 |
| A5 | 令牌/密码不落库 | 集成验证：`Authorization` 与 body 中 `password` 均为掩码 |
| A6 | 存储故障不丢数据 | 故障注入：Store 抛错 → WAL 有记录 + `spilled/deadletter` 指标 > 0 |
| A7 | 停机不丢队列 | 停机时 `flush` 并断言队列为空、WAL 已落盘 |
| A8 | 哈希链可校验、篡改可发现 | 集成验证：正常链通过；改一条记录字节 → 校验失败 |
| A9 | 静默失效被发现 | 启动期：模拟「HandlerMapping 有 @AuditLog 但未收录」→ 告警/报错 |
| A10 | SPI 可替换 | samples 提供自定义 `AuditStore`/`Masker`/`PrincipalResolver` → 被采用 |
| A11 | 全量采集下的性能有基线 | 提供四组对照压测脚本与报告模板（裸接口 / 全关 / 全开 / 含存储） |

## 6. 实施顺序

1. 父 POM + 三模块骨架 + LICENSE + 元数据
2. `core`：模型 → SPI → 脱敏 → 序列化 → 链 → 队列/背压/WAL → 默认 Store → 指标
3. `starter`：Properties → 自动配置 → 边界通道 → 语义通道 → 上下文传播 → 校验 → Actuator
4. `samples`：保留原端点 + 新增回滚/403/大报文/SPI 替换示例
5. 验证器（替代 offline 不可用的 surefire）：端到端 A1–A10
6. 文档：README / ADR / 迁移指南 / 压测方案
